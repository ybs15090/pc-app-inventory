# VS Code 用户配置建议

本文记录适合写入 VS Code 用户级 `settings.json` 的配置建议。用户级配置对所有工作区生效；仅针对单个项目的设置应写入项目的 `.vscode/settings.json`。

## 将 C/C++ IntelliSense 缓存迁移到其他磁盘

Microsoft C/C++ 扩展默认把 IntelliSense 缓存写入：

```text
%LOCALAPPDATA%\Microsoft\vscode-cpptools
```

该目录可能包含体积较大的 `.BROWSE.VC.DB` 索引数据库和 `.ipch` 预编译头缓存。需要节省 C 盘空间时，建议优先使用扩展提供的原生缓存路径设置，而不是建立 Junction。

### 推荐配置

在 VS Code 用户级 `settings.json` 中加入：

```jsonc
{
  "C_Cpp.intelliSenseCachePath": "E:\\Moved\\vscode-cpptools"
}
```

Windows 用户级配置文件通常位于：

```text
%APPDATA%\Code\User\settings.json
```

使用原生设置的优点：

- 配置含义明确，扩展升级后更容易维护。
- 不依赖 NTFS Junction，目标盘不可用时不会留下难以识别的目录联接。
- 可以直接从 VS Code 设置界面查看和修改。
- 适用于所有 C/C++ 工作区，无需逐项目配置。

不要同时为默认缓存目录建立 Junction 并设置 `C_Cpp.intelliSenseCachePath`，否则后续排查时难以确认扩展实际使用哪个位置。

### 安全迁移步骤

1. 正常关闭所有 VS Code 窗口，并确认 `Code.exe`、`cpptools.exe` 等相关进程已经退出。
2. 将默认缓存目录完整复制到新位置。
3. 对比源目录和目标目录的文件数量及总字节数。
4. 备份用户级 `settings.json`，再写入 `C_Cpp.intelliSenseCachePath`。
5. 只有在复制和配置校验均成功后，才删除 C 盘中的旧缓存副本。
6. 重新启动 VS Code，打开一个 C/C++ 项目，确认新缓存位置出现写入活动。

缓存内容可以重新生成。如果不需要保留现有索引，也可以在关闭 VS Code 后删除旧缓存，让扩展在新位置重新建立索引；首次打开大型项目时可能需要更长的分析时间。

### 缓存大小设置

C/C++ 扩展还提供 `C_Cpp.intelliSenseCacheSize`，用于限制预编译头缓存的近似大小。该设置主要约束 `.ipch` 缓存，并不保证整个 `vscode-cpptools` 目录不超过设定值，因为目录中还可能包含浏览数据库等文件。

本次迁移只修改缓存路径，没有调整缓存大小，以免改变 IntelliSense 性能表现。

### 回退方法

如果迁移后扩展不能正常工作：

1. 关闭 VS Code 和 C/C++ 扩展相关进程。
2. 恢复备份的 `settings.json`，或删除 `C_Cpp.intelliSenseCachePath`。
3. 将 `E:\Moved\vscode-cpptools` 移回默认缓存路径；也可以删除缓存，让扩展重新生成。
4. 重新启动 VS Code，并执行 `C/C++: Reset IntelliSense Database`。
