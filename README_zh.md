模板内容为中文。复制后替换占位内容、调整相对路径、删除不适用章节并更新目录。软件介绍的默认标题图片为 [占位图片](.media/占位图片.png)，路径从目标文档所在目录计算；需要时可替换为已确认的真实软件图标。软件说明、合集和专题默认提供开头目录，简短索引可省略。

### 仓库文件格式规范

**组织原则：**

- 软件条目应归入对应的平台目录（`Windows/`、`Linux/`、`MacOS/`、`General/`、`Android/` 或 `iOS/`）之下，并进一步归入 `Essential/`（必装）或 `Optional/`（选装）子目录。如果一款软件虽然支持多个平台，但其核心使用场景集中在某一平台上，也可按其主要使用平台归类。例如，Spacedesk 的主控端仅支持 Windows，因此归入 `Windows/` 目录。

- **单个独立软件**：直接在分类目录下创建 `软件名称.md` 文件，无需为其单独创建文件夹。  
  例如：`Linux/Optional/Distrobox容器软件.md`

- **单个软件，但带有附属资源**（如配置文件、截图等）：以软件名称创建文件夹，将 `.md` 主文档与附属资源文件一并放置其中。  
  例如：`General/Essential/VScode/` 目录内含 `vs-code.md`、`vscode-settings.json` 等。

- **功能相近的多款软件**（各软件篇幅较长）：以功能或用途命名创建文件夹，每款软件各自编写一份独立的 `.md` 文件。此类文件夹必须包含 `README.md`，用于列出该分类下收录的软件清单，并提供指向各软件文档的跳转链接。  
  例如：`General/Optional/network-proxy/` 目录内含 `Clash-Verge.md`、`v2rayA.md` 等，以及作为索引的 `README.md`。

- **功能相近的多款软件**（各软件篇幅较短）：可合并于一个 Markdown 文件中进行对比介绍，此时文件按功能或用途命名（如 `文件编辑.md`、`远程连接.md`），无需创建文件夹。

- 软件说明推荐包含以下内容；分类索引和配置专题使用对应模板，不强行加入安装章节：
  - 开头目录（与正文标题对应）
  - 软件简介
  - 官方文档链接（如有）
  - 其他相关资源链接（如教程、社区等）
  - 安装方法
  - 使用方法（简要说明即可）
  - 默认标题图片为 `.media/占位图片.png`，其他媒体资源放入 `.media/` 的对应文件夹

- 新增文档时同步所属目录和必要的上级 `README.md`；移动或重命名文件时更新所有引用。根 README 的中英文正文保持对应，模板不要求另建英文副本。

- 所有软件说明必须在前 20 行内设置唯一的 `<!-- software-count: N -->`，建议放在第一行：单软件为 `1`，合集为实际数量，配置或非软件专题为 `0`。脚本不根据图片、标题或文件名推断数量，缺失标签的正文未计入且会阻止刷新。统计表由 `scripts/count-software.py` 更新 `software-stats` 标记之间的区块，不手改数字。

- 本次提供模板和新稿约定，既有文档不批量重排。编辑时尽量保留编码和换行，所有操作忽略 `.obsidian/`。
